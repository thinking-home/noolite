# История изменений

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), проект следует
[семантическому версионированию](https://semver.org/lang/ru/).

Изменения версий ниже 5.0.0 в этом файле не восстанавливались — см.
[историю коммитов](https://github.com/thinking-home/noolite/commits/master).

## [5.0.0] — 2026-08-18

Мажорный релиз. Требуется .NET 10. Изменения, требующие правок в коде потребителя, помечены
**[ломающее]**.

### Изменено

- **[ломающее]** Целевая платформа `net9.0` → `net10.0`, зависимость `System.IO.Ports`
  `9.0.1` → `10.0.11`. Потребителю нужен .NET 10.

- **[ломающее]** Обработчики входящих пакетов вызываются из **фонового потока доставки**,
  а не из потока, читающего порт. Обработчики вызываются по одному и в порядке прихода пакетов;
  для одного пакета сначала `ReceiveData`, затем типизированное событие. Долгий обработчик больше
  не тормозит приём следующих пакетов, отправку команд и закрытие адаптера.

  *Что делать:* если обработчик обращается к состоянию, привязанному к потоку (UI, не
  потокобезопасные коллекции), добавить явную синхронизацию — раньше вызовы приходили
  из потока таймера чтения.

- **[ломающее]** `Close()` и `Dispose()` закрывают порт немедленно и **отбрасывают** пакеты,
  принятые, но ещё не доставленные обработчикам. Вызов возвращается сразу после закрытия порта
  и не дожидается события `Disconnect` — оно приходит вскоре из потока доставки и остаётся
  последним событием адаптера.

  *Что делать:* там, где терять принятое нельзя, заменить `Close()` или выход из `using`
  на `await FlushAndCloseAsync()`.

- **[ломающее]** `ReceivedData.Remains` изменил тип с `int` на `int?` и смысл. Раньше свойство
  возвращало `0` для режимов RX/RXF и сырой байт TOGL для всех остальных режимов. Теперь оно
  осмысленно только для режимов TX/TXF, а для прочих равно `null`.

  *Что делать:* для счётчика команд передатчика в режимах RX/RXF использовать новое свойство
  `ToggleCounter`, для сырого байта — новое свойство `Togl`.

- **[ломающее]** Конструктор `MTRFXXAdapter(string portName)` получил второй необязательный
  параметр — `queueCapacity`. Совместимо на уровне исходного кода, но не двоично: потребителя
  нужно пересобрать.

- **[ломающее]** Очередь принятых пакетов ограничена — по умолчанию 128 пакетов. При переполнении
  новый пакет отбрасывается, уже принятые сохраняются в порядке прихода. Раньше приём
  не имел предела.

  *Что делать:* если обработчики медленные, а всплески трафика большие, увеличить ёмкость вторым
  параметром конструктора и следить за `DroppedPacketsCount`.

- Запись команды в порт атомарна относительно других записей и относительно чтения входящих
  пакетов: байты команд, отправленных из разных потоков, больше не могут чередоваться.
  Запись ограничена таймаутом 500 мс — отключённый от USB адаптер больше не блокирует
  отправку и приём бесконечно.

- Утилита `noolite` завершает работу через `FlushAndCloseAsync()`: перед выходом дожидается
  обработки принятых пакетов вместо того, чтобы отбросить их вместе с закрытием порта.

- Утилита `noolite` возвращает нулевой код возврата при успешном выполнении команды и ненулевой
  при отказе.

### Добавлено

- `FlushAndCloseAsync(CancellationToken)` — закрывает порт и дожидается доставки уже принятых
  пакетов; по возврату очередь пуста и `Disconnect` вызван. Вызов изнутри обработчика события
  бросает `InvalidOperationException`.

- `ReadStateF(channel, deviceId, format)` — запрос состояния силовых блоков nooLite-F: по каналу,
  адресно или широковещательно.

- События `ReceivePowerUnitState` (`PowerUnitStateData`: `DeviceType`, `FirmwareVersion`, `State`,
  `ServiceMode`, `PowerLevel`) и `ReceiveStateFormatError` (`StateFormatErrorData`) — типизированные
  ответы на запрос состояния.

- `ReceivedData.ToggleCounter` — счётчик команд передатчика для режимов RX/RXF; у повторов одной
  посылки значение одинаково.

- `ReceivedData.Togl` — сырой байт TOGL без интерпретации, доступен для любого режима.

- `DroppedPacketsCount` — число пакетов, отброшенных при переполнении очереди приёма,
  и константа `DEFAULT_QUEUE_CAPACITY`.

- Утилита `noolite`: команды `temporary-on`, `switch-color-changing`, `change-color-mode`,
  `change-color-speed`, `bind-start`, `bind-stop`, `clear-channel`, `clear-all`. Команды работы
  с передающими устройствами (`bind-start`, `bind-stop`, `clear-channel`, `clear-all`) работают
  только в режиме приёма и не принимают флаг `-f`.

- Утилита `noolite`: опция `--version`.

### Исправлено

- Исключение из обработчика события больше не прерывает приём: оно попадает в событие `Error`,
  остальные обработчики и следующие пакеты обрабатываются как обычно.

- `Disconnect` гарантированно последнее событие адаптера: обработчики пакета, обработка которого
  началась в момент закрытия, доводятся до конца — включая типизированные события этого пакета.

- Утилита `noolite` печатает причину отказа при открытии порта. Раньше настоящая ошибка терялась
  в событии `Error`, а наружу выходило постороннее сообщение `The port is closed`.

- Утилита `noolite` сообщает о пропущенном обязательном аргументе и печатает справку по команде.
  Раньше вызов без аргументов завершался необработанным `ArgumentNullException`.

- Утилита `noolite` печатает сообщение об ошибке вместо стека вызовов.
