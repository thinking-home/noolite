# Выпуск релиза

Пакеты `ThinkingHome.NooLite` и `ThinkingHome.NooLite.Console` публикуются в NuGet воркфлоу
[`.github/workflows/release.yml`](../.github/workflows/release.yml). Он запускается **только
вручную** и использует Trusted Publishing: долгоживущий API-ключ не хранится ни в секретах,
ни где-либо ещё — воркфлоу обменивает OIDC-токен GitHub на временный ключ, действующий один час.

## Однократная настройка

Без неё публикация упадёт на шаге `NuGet login`.

### 1. Политика Trusted Publishing на nuget.org

Войти на nuget.org → имя пользователя → **Trusted Publishing** → добавить политику:

| Поле              | Значение        |
|-------------------|-----------------|
| Repository Owner  | `thinking-home` |
| Repository        | `noolite`       |
| Workflow File     | `release.yml`   |
| Environment       | *(пусто)*       |

Имя файла воркфлоу указывается **без** пути `.github/workflows/`. Владельцем политики нужно
выбрать того, кому принадлежат пакеты `ThinkingHome.NooLite` на nuget.org: политика действует
на все пакеты выбранного владельца.

Переименование `release.yml` сломает публикацию — политику придётся заводить заново.

### 2. `NUGET_USER` в репозитории

Settings → Secrets and variables → Actions:

- имя: `NUGET_USER`
- значение: **имя пользователя** на nuget.org (profile name), **не** адрес электронной почты

Годится любая из двух вкладок — воркфлоу читает `vars.NUGET_USER`, а если пусто, то
`secrets.NUGET_USER`. По смыслу это **не секрет**: имя владельца пакета и так видно на его
странице в nuget.org, поэтому вкладка **Variables** уместнее.

Частая ошибка: значение заведено на вкладке Variables, а воркфлоу читает только `secrets.*` —
`NuGet/login` падает с `Input required and not supplied: user`. Вторая частая причина той же
ошибки — значение заведено на уровне организации `thinking-home` с политикой доступа
«Selected repositories», в которую не включён `noolite`.

## Как выпустить релиз

1. Добавить в [`CHANGELOG.md`](../CHANGELOG.md) секцию новой версии с датой.
2. Поднять `VersionPrefix` в [`Package.xml`](../Package.xml). Версия одна на оба пакета.
3. Закоммитить и запушить в `master`.
4. Actions → **Release** → Run workflow → ввести ту же версию, что в `Package.xml`.

Воркфлоу собирает решение, прогоняет тесты, пакует оба пакета и публикует их в nuget.org.

## Что проверяется до сборки

**Выложенный в NuGet пакет удалить нельзя** — версию можно только скрыть из поиска (unlist),
а занятый номер версии больше никогда не освободится. Поэтому до сборки воркфлоу проверяет два
условия и падает, если хоть одно нарушено:

- запуск идёт из ветки `master` (`workflow_dispatch` позволяет выбрать любую ветку, и без этой
  проверки можно было бы опубликовать код из случайной ветки под номером релизной версии);
- введённая при запуске версия совпадает с `VersionPrefix` в `Package.xml`.

Ручного подтверждения перед выкладкой нет: гейтом служит сам ручной запуск. Если понадобится
ещё один барьер — завести в настройках репозитория environment `release` с обязательным
review, добавить `environment: release` в job и указать то же имя в поле Environment политики
на nuget.org.

## Повторный запуск

Публикация идёт с `--skip-duplicate`: если один пакет уже выложен, а второй нет, повторный
запуск доложит недостающий и не упадёт на уже существующем.
