## ADDED Requirements

### Requirement: Обработчик события не блокирует приём и отправку

Библиотека SHALL вызывать обработчики событий входящих пакетов вне критической секции,
в которой выполняются чтение из порта, запись команд и открытие/закрытие порта. Длительность
работы обработчика MUST NOT влиять на приём следующих пакетов из порта, на отправку команд
из других потоков и на закрытие адаптера.

Пакеты MUST доходить до обработчиков в том порядке, в каком они приняты из порта; обработчики
одного пакета MUST вызываться последовательно, а не параллельно.

#### Scenario: Медленный обработчик и отправка

- **WHEN** обработчик события выполняется дольше периода опроса порта, а другой поток в это
  время вызывает отправку команды
- **THEN** отправка выполняется, не дожидаясь завершения обработчика

#### Scenario: Медленный обработчик и приём

- **WHEN** обработчик события выполняется, а в порт приходят новые пакеты
- **THEN** новые пакеты вычитываются из порта и ставятся в очередь, не дожидаясь обработчика
- **AND** после завершения обработчика они доходят до обработчиков в порядке прихода

#### Scenario: Порядок при нескольких пакетах

- **WHEN** из порта приняты пакеты A, B, C подряд
- **THEN** обработчики получают A, затем B, затем C — независимо от того, сколько времени
  занял каждый

### Requirement: Изоляция обработчиков

Исключение в одном обработчике события MUST NOT препятствовать вызову остальных обработчиков
того же пакета, обработке следующих пакетов и работе адаптера. Такое исключение SHALL быть
доставлено потребителю через событие ошибки. Исключение внутри самого обработчика ошибки
SHALL быть подавлено — иначе один сбойный обработчик остановил бы доставку всех событий.

#### Scenario: Обработчик бросил исключение

- **WHEN** обработчик общего события бросил исключение для пакета, у которого есть
  типизированный разбор
- **THEN** исключение доставляется через событие ошибки
- **AND** типизированное событие для того же пакета всё равно вызывается
- **AND** следующие пакеты обрабатываются

#### Scenario: Обработчик ошибки бросил исключение

- **WHEN** обработчик события ошибки сам бросил исключение
- **THEN** оно подавляется, доставка событий продолжается

### Requirement: Ограниченная очередь входящих пакетов

Принятые из порта пакеты SHALL накапливаться в очереди ограниченной ёмкости, задаваемой при
создании адаптера; ёмкость по умолчанию — 128 пакетов. При переполнении библиотека SHALL
отбрасывать **самый старый** пакет из очереди, освобождая место для нового: свежее состояние
ценнее истории. Число отброшенных пакетов SHALL быть доступно потребителю через счётчик.

Постановка пакета в очередь MUST NOT блокировать поток чтения — переполнение разрешается
отбрасыванием, а не ожиданием.

#### Scenario: Очередь переполнена

- **WHEN** очередь заполнена, а из порта принят ещё один пакет
- **THEN** самый старый пакет очереди отбрасывается, новый ставится в конец
- **AND** счётчик отброшенных увеличивается на единицу
- **AND** поток чтения не блокируется

#### Scenario: Ёмкость по умолчанию

- **WHEN** адаптер создан без указания ёмкости очереди
- **THEN** ёмкость равна 128

### Requirement: Закрытие адаптера и судьба очереди

Библиотека SHALL предоставлять два способа закрытия, различающиеся судьбой ещё не обработанных
пакетов:

- **немедленное** — порт закрывается сразу, необработанные пакеты **отбрасываются**, событие
  отключения вызывается, вызов возвращается. Это поведение по умолчанию и поведение при
  освобождении адаптера (`Dispose`): после закрытия состояние потребителя может быть
  непригодно для обработчиков, и библиотека не может этого знать;
- **с обработкой остатка** — порт закрывается так же сразу (новых пакетов не поступает),
  но вызов дожидается, пока все уже принятые пакеты будут доставлены обработчикам, затем
  вызывает событие отключения и возвращается. По возврату очередь MUST быть пуста.
  Отмена ожидания через токен отмены — остаток отбрасывается.

В обоих случаях событие отключения MUST быть последним событием адаптера: после него
обработчики входящих пакетов не вызываются.

Вызов закрытия с обработкой остатка изнутри обработчика события MUST завершаться исключением:
иначе диспетчер ждал бы завершения самого себя.

#### Scenario: Немедленное закрытие с непустой очередью

- **WHEN** в очереди лежат необработанные пакеты и вызвано немедленное закрытие
- **THEN** порт закрыт, эти пакеты не доходят до обработчиков, событие отключения вызвано
- **AND** после события отключения обработчики входящих пакетов не вызываются

#### Scenario: Закрытие с обработкой остатка

- **WHEN** в очереди лежат необработанные пакеты и вызвано закрытие с обработкой остатка
- **THEN** порт закрыт немедленно
- **AND** все пакеты из очереди доходят до обработчиков в порядке прихода
- **AND** затем вызывается событие отключения, затем вызов возвращается

#### Scenario: Отмена ожидания

- **WHEN** закрытие с обработкой остатка ожидает медленный обработчик, а токен отмены сработал
- **THEN** ожидание прерывается, остаток очереди отбрасывается, порт остаётся закрытым

#### Scenario: Закрытие с обработкой остатка из обработчика

- **WHEN** обработчик события пакета вызывает закрытие с обработкой остатка и синхронно ждёт
  его завершения
- **THEN** вызов завершается исключением, а не взаимной блокировкой

#### Scenario: Освобождение адаптера

- **WHEN** адаптер освобождается (`Dispose`) с непустой очередью
- **THEN** поведение как при немедленном закрытии: остаток отбрасывается
