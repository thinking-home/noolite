## Purpose

Отправка команд адаптеру MTRF-64-USB: как формируется пакет, при каких условиях он гарантированно
уходит в порт целиком, и как потребитель узнаёт, что команда не была отправлена.

## ADDED Requirements

### Requirement: Атомарность записи пакета

Библиотека SHALL записывать каждый командный пакет в последовательный порт целиком и неделимо
по отношению к другим записям. Байты двух команд, отправленных одновременно из разных потоков,
MUST NOT чередоваться в потоке, который получает адаптер.

Порядок, в котором уходят конкурирующие команды, не определён: библиотека гарантирует только
целостность каждого отдельного пакета, но не последовательность между вызывающими сторонами.

#### Scenario: Две команды из разных потоков

- **WHEN** два потока одновременно вызывают отправку команды на одном экземпляре адаптера
- **THEN** адаптер получает два целых пакета — сначала один полностью, затем другой полностью
- **AND** ни один пакет не содержит байтов другого

#### Scenario: Отправка во время приёма входящих данных

- **WHEN** команда отправляется в момент, когда библиотека вычитывает входящие пакеты из порта
- **THEN** отправка и чтение не искажают данные друг друга
- **AND** обе операции завершаются

### Requirement: Ограничение времени записи

Запись пакета SHALL завершаться за ограниченное время. Библиотека MUST NOT блокироваться
на записи бесконечно, даже если адаптер перестал принимать данные — например, при физическом
отключении от USB.

Это требование существует потому, что запись выполняется взаимоисключающе с приёмом входящих
пакетов: неограниченное ожидание на записи остановило бы приём целиком, а не только отправку.

#### Scenario: Адаптер перестал принимать данные

- **WHEN** отправка вызвана, а устройство не забирает данные из порта
- **THEN** попытка записи прекращается по истечении ограниченного времени
- **AND** вызывающая сторона получает ошибку
- **AND** приём входящих пакетов продолжает работать после этого

### Requirement: Сообщение об ошибке отправки вызывающей стороне

Отправка команды SHALL сообщать вызывающей стороне об ошибке исключением. Библиотека MUST NOT
завершать вызов отправки успешно, если пакет не был записан в порт.

Это отличается от операций подключения и приёма, где ошибки доставляются через событие `Error`:
для команд управления потребителю необходимо достоверно знать, ушла команда или нет, чтобы
принимать решение о повторе.

#### Scenario: Отправка при закрытом порту

- **WHEN** отправка вызвана до открытия порта или после его закрытия
- **THEN** вызывающая сторона получает исключение
- **AND** вызов не завершается успешно молча

#### Scenario: Ошибка ввода-вывода при записи

- **WHEN** запись в порт завершается ошибкой ввода-вывода
- **THEN** вызывающая сторона получает исключение

### Requirement: Формат командного пакета

Библиотека SHALL формировать командный пакет длиной 17 байт со стартовым маркером, режимом,
действием с числом повторов, каналом, кодом команды, форматом данных, четырьмя байтами данных,
четырёхбайтным адресом устройства, контрольной суммой и стоповым маркером.

Контрольная сумма MUST быть младшим байтом суммы первых пятнадцати байт пакета.

#### Scenario: Сборка пакета

- **WHEN** формируется пакет для любой поддерживаемой команды
- **THEN** его длина равна 17 байтам
- **AND** контрольная сумма равна младшему байту суммы первых пятнадцати байт
