## Purpose

Консольная утилита `noolite` даёт доступ к возможностям библиотеки из командной строки и скриптов:
какие команды доступны, в какой форме задаются их аргументы, как утилита завершает работу
с адаптером и как сообщает вызывающей стороне об успехе или ошибке.

## ADDED Requirements

### Requirement: Полное покрытие операций отправки командами

Утилита SHALL предоставлять команду для каждой операции отправки, доступной в публичном API
библиотеки:

- управление нагрузкой: включение, выключение, инверсия состояния, включение на время,
  установка яркости, запоминание и применение сценария освещения;
- управление RGB-лентой: установка цвета, переход к следующему цвету, включение плавной смены
  цветов, смена режима, смена скорости;
- привязка силовых блоков: привязка и отвязка;
- работа с передающими устройствами: вход в режим привязки, выход из режима привязки, очистка
  привязок в канале, очистка привязок во всех каналах.

Утилита MUST NOT оставлять операцию отправки из публичного API библиотеки без соответствующей
команды.

Выход из сервисного режима не является отдельной командой: утилита выполняет его самостоятельно
при подготовке адаптера к отправке.

#### Scenario: Команда доступна для каждой операции отправки

- **WHEN** пользователь запрашивает список команд утилиты
- **THEN** в списке присутствует команда для каждой операции отправки из публичного API библиотеки
- **AND** у каждой команды есть описание назначения

#### Scenario: Включение на время

- **WHEN** пользователь вызывает команду включения на время, указав порт, канал и длительность
- **THEN** адаптеру уходит команда включения нагрузки на заданный интервал в указанном канале

#### Scenario: Очистка привязок во всех каналах

- **WHEN** пользователь вызывает команду очистки всех каналов, указав порт
- **THEN** адаптеру уходит команда очистки привязанных передающих устройств во всех каналах

### Requirement: Форма аргументов команд управления

Команда управления нагрузкой, RGB-лентой или привязкой силового блока SHALL принимать имя
последовательного порта и номер канала адаптера как позиционные аргументы, а режим nooLite-F —
как флаг. Собственные параметры команды (уровень яркости, компоненты цвета, длительность
включения) SHALL следовать за номером канала позиционными аргументами.

Без флага режима команда SHALL отправляться в стандартном режиме nooLite, с флагом — в режиме
nooLite-F.

#### Scenario: Отправка в стандартном режиме

- **WHEN** команда вызвана с портом и каналом, без флага режима nooLite-F
- **THEN** адаптеру уходит команда в стандартном режиме nooLite

#### Scenario: Отправка в режиме nooLite-F

- **WHEN** та же команда вызвана с флагом режима nooLite-F
- **THEN** адаптеру уходит та же команда в режиме nooLite-F

#### Scenario: Пропущен обязательный аргумент

- **WHEN** команда вызвана без имени порта или без номера канала
- **THEN** утилита сообщает об ошибке разбора командной строки
- **AND** команда адаптеру не отправляется

### Requirement: Команды работы с передающими устройствами без выбора режима

Команды входа в режим привязки, выхода из режима привязки, очистки канала и очистки всех каналов
SHALL работать только в режиме приёма и MUST NOT принимать флаг режима nooLite-F: библиотека
не предоставляет для этих операций F-вариантов.

Команды выхода из режима привязки и очистки всех каналов SHALL принимать только имя порта:
номер канала для них не имеет смысла.

#### Scenario: Флаг режима не предлагается

- **WHEN** пользователь запрашивает справку по команде входа в режим привязки
- **THEN** в списке её параметров отсутствует флаг режима nooLite-F

#### Scenario: Команда без канала

- **WHEN** пользователь вызывает команду выхода из режима привязки, указав только имя порта
- **THEN** команда выполняется
- **AND** утилита не требует номер канала

### Requirement: Завершение без отбрасывания принятого

Перед завершением работы утилита SHALL закрывать соединение с адаптером способом, который
дожидается обработки уже принятых пакетов. Утилита MUST NOT завершаться так, что принятые,
но необработанные пакеты отбрасываются.

Требование существует потому, что ошибки библиотека доставляет асинхронно: при закрытии
с отбрасыванием ошибка, обнаруженная в уже принятых данных, не успела бы попасть в вывод
и в код возврата.

#### Scenario: На момент закрытия остались необработанные пакеты

- **WHEN** команда отправлена и утилита переходит к завершению, а принятые пакеты ещё не обработаны
- **THEN** утилита дожидается их обработки
- **AND** только после этого завершает работу

#### Scenario: Ошибка обнаружена при обработке принятого

- **WHEN** при обработке принятых пакетов возникает ошибка
- **THEN** утилита успевает сообщить о ней до завершения

### Requirement: Код возврата и сообщение об ошибке

Утилита SHALL возвращать нулевой код возврата, если запрошенная команда выполнена, и ненулевой,
если выполнить её не удалось.

При ошибке утилита SHALL печатать в поток ошибок сообщение, объясняющее причину. Утилита
MUST NOT показывать пользователю необработанное исключение со стеком вызовов.

#### Scenario: Успешное выполнение команды

- **WHEN** команда отправлена адаптеру без ошибок
- **THEN** код возврата равен нулю

#### Scenario: Порт недоступен

- **WHEN** команда вызвана с именем несуществующего или занятого порта
- **THEN** утилита печатает в поток ошибок сообщение о невозможности работать с этим портом
- **AND** код возврата отличен от нуля
- **AND** стек вызовов пользователю не показывается

#### Scenario: Ошибка разбора командной строки

- **WHEN** команда вызвана с нераспознанными или недостающими аргументами
- **THEN** утилита печатает сообщение об ошибке и справку
- **AND** код возврата отличен от нуля

### Requirement: Отображение версии утилиты

Справка утилиты SHALL показывать фактическую версию, с которой опубликован пакет. Отображаемая
версия MUST соответствовать версии пакета во всех её компонентах.

#### Scenario: Версия с ненулевым патч-компонентом

- **WHEN** пакет опубликован с версией, у которой патч-компонент отличен от нуля,
  и пользователь запрашивает справку
- **THEN** показанная версия совпадает с версией пакета, включая патч-компонент

### Requirement: Список последовательных портов

Утилита SHALL предоставлять команду, которая печатает имена последовательных портов, доступных
на этом компьютере, и не требует подключённого адаптера.

#### Scenario: Запрос списка портов

- **WHEN** пользователь вызывает команду списка портов
- **THEN** утилита печатает имена доступных последовательных портов
- **AND** не пытается открыть соединение с адаптером
