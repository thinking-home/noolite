## Why

Библиотека готова к мажорному релизу: шесть change'ов (`update-to-net10`, `thread-safe-send`,
`read-state`, `async-receive`, `port-abstraction`, `dispatcher-lifecycle`) завершены и заархивированы,
тесты зелёные. Но релиз выпустить нельзя: версия пакета осталась `4.4.0`, описания ломающих изменений
для потребителей нет, а консольная утилита `noolite` отстала от библиотеки — она закрывает адаптер
по устаревшей схеме (теряя принятые пакеты), не покрывает командами треть публичного API и падает
стектрейсом на бытовых ошибках вроде неверного имени порта.

## What Changes

**Гигиена CLI**

- Замена схемы закрытия адаптера: сейчас `Invoke()` использует `using` + `Thread.Sleep(100)` → `Dispose()`.
  По семантике, принятой в `dispatcher-lifecycle`, `Dispose()` закрывает порт немедленно и **отбрасывает**
  недоставленные пакеты. Переход на `FlushAndCloseAsync()` — утилита дожидается доставки принятого.
- Обработка ошибок: сейчас перехватывается только `CommandParsingException`. Ошибки адаптера
  (порт не найден, порт занят, таймаут записи) выпадают наружу необработанным исключением. Утилита
  SHALL печатать сообщение об ошибке и возвращать ненулевой код возврата.
- Строка версии в `--help` собирается как `v{Major}.{Minor}.{Revision}` — берётся не тот компонент,
  для версии `5.1.2` покажет `v5.1.0`. Привести к фактической версии пакета.

**Паритет команд с публичным API**

Новые команды на методы, не покрытые CLI:

- `temporary-on` (`TemporarySwitchOn`/`TemporarySwitchOnF`) — включение на время;
- `switch-color-changing` (`SwitchColorChanging`/`F`), `change-color-mode` (`ChangeLedColorMode`/`F`),
  `change-color-speed` (`ChangeLedColorSpeed`/`F`) — режимы RGB-ленты;
- `bind-start` (`BindStart`), `bind-stop` (`BindStop`), `clear-channel` (`ClearChannel`),
  `clear-all` (`ClearAllChannels`) — привязка передающих устройств и очистка каналов.

Последние четыре работают в режиме RX и **не имеют F-вариантов** в библиотеке, а `bind-stop`
и `clear-all` не принимают номер канала. Их набор аргументов отличается от остальных команд:
у них нет флага `-f`, а у двух нет аргумента `channel`. Это следствие текущего API библиотеки,
а не решение этого change'а.

**Релизные артефакты**

- `CHANGELOG.md` — новый файл: ломающие изменения 4.4 → 5.0 для потребителей библиотеки
  (переход на `net10.0`; события из фонового потока по одному; изменённая семантика
  `Close()`/`Dispose()` и новый `FlushAndCloseAsync()`; `Remains` `int` → `int?`, новые
  `ToggleCounter` и `Togl`; типизированный API состояния `ReadStateF` / `ReceivePowerUnitState` /
  `ReceiveStateFormatError`; ограниченная очередь приёма и `DroppedPacketsCount`) и изменения CLI
  из этого change'а. **BREAKING** — перечисленные изменения библиотеки уже в коде, здесь они
  только документируются.
- `Package.xml`: `VersionPrefix` `4.4.0` → `5.0.0`.

**Вне объёма**

- Команды чтения (`state` на `ReadStateF`, `listen` на мониторинг входящих пакетов) — CLI остаётся
  «только отправка команд». Решение владельца проекта.
- Настройка CI на сборку и публикацию пакетов в NuGet через Trusted Publishing — отдельная работа
  следующим шагом.
- Изменения публичного API библиотеки. Код библиотеки этот change не трогает.

## Capabilities

### New Capabilities

- `cli`: поведение консольной утилиты `noolite` — набор команд и их аргументы, порядок работы
  с адаптером (открытие, отправка, закрытие без потери принятого), коды возврата и сообщения
  об ошибках.

### Modified Capabilities

Нет. Поведение библиотеки не меняется: `command-sending` и `packet-receiving` остаются как есть.
CLI — потребитель этих спек, а не их часть.

## Impact

- `ThinkingHome.NooLite.Console/Program.cs` — единственный файл с кодом, который меняется:
  переработка `Invoke()`, обработка ошибок и коды возврата, строка версии, ~8 новых команд.
- `ThinkingHome.NooLite.Console/ThinkingHome.NooLite.Console.csproj` — возможно, свойства версии
  для корректного отображения в `--help`.
- `Package.xml` — версия пакетов; затрагивает оба публикуемых пакета
  (`ThinkingHome.NooLite` и `ThinkingHome.NooLite.Console`).
- `CHANGELOG.md` — новый файл в корне репозитория.
- `README.md` — раздел «Интерфейс командной строки» перечисляет команды и потому расходится
  с новым набором.
- Код библиотеки `ThinkingHome.NooLite` и тесты — **не затрагиваются**. Публичный API библиотеки
  не меняется, 76 существующих тестов должны остаться зелёными.
- Потребитель библиотеки — драйвер NooLite в `ThinkingHome.DeviceModel`: получает мажорную версию
  и `CHANGELOG.md` как инструкцию по миграции.
