## MODIFIED Requirements

### Requirement: Закрытие адаптера и судьба очереди

Библиотека SHALL предоставлять два способа закрытия, различающиеся судьбой ещё не обработанных
пакетов:

- **немедленное** — порт закрывается сразу, необработанные пакеты **отбрасываются**, вызов
  возвращается, **не дожидаясь** события отключения. Событие отключения вызывается вскоре после
  этого из того же потока, что доставляет события пакетов. Это поведение по умолчанию и поведение
  при освобождении адаптера (`Dispose`): после закрытия состояние потребителя может быть
  непригодно для обработчиков, и библиотека не может этого знать. По возврату вызова порт MUST
  быть закрыт; потребитель, которому нужно дождаться завершения, подписывается на событие
  отключения;
- **с обработкой остатка** — порт закрывается так же сразу (новых пакетов не поступает),
  но вызов дожидается, пока все уже принятые пакеты будут доставлены обработчикам, затем
  происходит событие отключения, затем вызов возвращается. По возврату очередь MUST быть пуста,
  а событие отключения уже MUST быть вызвано. Отмена ожидания через токен отмены — остаток
  отбрасывается, событие отключения всё равно происходит.

Событие отключения MUST быть последним событием адаптера. Обработчики пакета, обработка которого
уже началась в момент закрытия, MUST быть доведены до конца — включая типизированные события
этого пакета — и только затем MUST произойти событие отключения. После события отключения ни один
обработчик входящего пакета не вызывается.

Немедленное закрытие изнутри обработчика события MUST быть безопасным: оно публикует запрос
и возвращается, ничего не ожидая. Закрытие с обработкой остатка изнутри обработчика MUST
завершаться исключением: иначе поток доставки ждал бы завершения самого себя.

#### Scenario: Немедленное закрытие с непустой очередью

- **WHEN** в очереди лежат необработанные пакеты и вызвано немедленное закрытие
- **THEN** по возврату вызова порт закрыт, эти пакеты не доходят до обработчиков
- **AND** событие отключения вызывается (вскоре, из потока доставки) и является последним
- **AND** после события отключения обработчики входящих пакетов не вызываются

#### Scenario: Немедленное закрытие не ждёт отключения

- **WHEN** обработчик пакета выполняется, и в этот момент вызвано немедленное закрытие
- **THEN** вызов закрытия возвращается, не дожидаясь ни завершения обработчика, ни события
  отключения

#### Scenario: Типизированное событие пакета при закрытии в момент его обработки

- **WHEN** немедленное закрытие вызвано, пока выполняется обработчик общего события пакета,
  у которого есть типизированный разбор
- **THEN** типизированное событие этого пакета всё равно доставляется
- **AND** событие отключения происходит уже после него

#### Scenario: Закрытие с обработкой остатка

- **WHEN** в очереди лежат необработанные пакеты и вызвано закрытие с обработкой остатка
- **THEN** порт закрыт немедленно
- **AND** все пакеты из очереди доходят до обработчиков в порядке прихода
- **AND** затем происходит событие отключения, затем вызов возвращается

#### Scenario: Отмена ожидания

- **WHEN** закрытие с обработкой остатка ожидает медленный обработчик, а токен отмены сработал
- **THEN** ожидание прерывается, остаток очереди отбрасывается, порт остаётся закрытым
- **AND** событие отключения всё равно происходит

#### Scenario: Немедленное закрытие из обработчика

- **WHEN** обработчик события пакета вызывает немедленное закрытие
- **THEN** вызов возвращается без исключения и без взаимной блокировки
- **AND** адаптер закрывается, событие отключения происходит после завершения обработчиков
  текущего пакета

#### Scenario: Закрытие с обработкой остатка из обработчика

- **WHEN** обработчик события пакета вызывает закрытие с обработкой остатка и синхронно ждёт
  его завершения
- **THEN** вызов завершается исключением, а не взаимной блокировкой

#### Scenario: Освобождение адаптера

- **WHEN** адаптер освобождается (`Dispose`) с непустой очередью
- **THEN** поведение как при немедленном закрытии: остаток отбрасывается, событие отключения
  вызывается из потока доставки и является последним
